# Smoke-check и скриншоты

Протокол итоговой проверки по разделу «Контролируемый smoke-check» из [spec.md](../spec.md). По spec.md результат существует только после фактического наблюдения, а не по ответу ИИ. Поэтому колонку «Факт» заполняет студент.

## Подготовка

1. Остановите сервер, если он запущен, и удалите `boris.db`, чтобы начать с чистого состояния.
2. Запустите `npm start` и откройте `http://localhost:3100` в основном браузере (браузер А).
3. **Сразу**, до шага 2 протокола, откройте ту же страницу во втором браузере (браузер Б), например в Safari, если А — Chrome. Не обновляйте Б до шага 3: только на «устаревшей» странице можно попытаться занять уже занятый слот.

## Семь скриншотов

Сохраняйте в `docs/screenshots/` под указанными именами. На каждом скриншоте должен быть виден адрес `localhost` и только синтетические ФИО.

| Файл | DoD | Что должно быть в кадре |
|---|---|---|
| `01-date-five-slots.png` | 1 | Дата и пять свободных слотов (шаг 1) |
| `02-free-and-booked.png` | 2 | На одном экране свободный и занятый слот с ФИО (после шага 2) |
| `03-booking-success.png` | 3 | Сообщение «Вы записаны на 11:00: Анна Тестова» и занятый слот |
| `04-conflict.png` | 4 | Браузер Б: «Слот занят», в `11:00` «Анна Тестова» |
| `05-second-browser.png` | 5 | Та же запись во втором браузере или после обновления; виден другой браузер |
| `06-feeding-card.png` | 6 | Карточка «Последнее кормление» после новой отметки и сообщение «Кормление отмечено» |
| `07-narrow-screen.png` | 7 | Главный сценарий на ~375px: свободный слот с кнопкой, занятый слот, без обрезаний |

Список предварительный, по одному скриншоту на DoD. Сверьте его с требованиями курса.
