# Кто выгуливает Бориса

Учебный micro-MVP на Node.js для вымышленной компании «Догяндекс». В московском офисе работают 111 человек и живёт пёс Борис. На одной общей странице сотрудник записывается на прогулку с Борисом и отмечает кормление.

Требования к продукту описаны в [spec.md](spec.md), правила работы с ИИ-агентом — в [AGENTS.md](AGENTS.md). Этапы, статусы и проверки ведутся в [PLAN.md](PLAN.md).

> **Статус:** готовы этапы 1–3 в PLAN.md. Страница показывает текущую дату и пять слотов из SQLite, свободные и занятые различаются. Запись в слот и карточка кормления ещё не реализованы.

## Что умеет приложение

- Показывает текущую дату по московскому времени.
- Показывает ровно пять слотов прогулок на сегодня: `09:00`, `11:00`, `13:00`, `15:00`, `17:00`.
- Свободный и занятый слоты выглядят по-разному. У занятого слота видно ФИО.
- В свободный слот можно записаться, указав ФИО.
- Повторная запись в занятый слот отклоняется сервером с сообщением «Слот занят». Исходная запись не меняется.
- Карточка «Последнее кормление» показывает время и ФИО. Новое кормление отмечается по ФИО, время ставит сервер в момент отметки.
- Всё состояние хранится в SQLite-файле. Оно сохраняется после обновления страницы и видно из другого браузера.

## Запуск

Требуется Node.js 24 и npm. Проверено на Node.js v24.18.0 и npm 11.16.0. Внешних зависимостей нет: для SQLite используется встроенный модуль Node.js `node:sqlite`.

```bash
npm install
```

```bash
npm start
```

Затем откройте `http://localhost:3100`. Сервер доступен только с этого компьютера (`127.0.0.1`). Остановить его можно сочетанием `Ctrl+C` в терминале.

Если порт 3100 занят, сервер сообщит об этом и завершится. Тогда запустите его на другом порту и откройте `http://localhost:3200`:

```bash
PORT=3200 npm start
```

При первом запуске в папке проекта создаётся файл базы `boris.db` и пять свободных слотов на текущую московскую дату. Файл базы не хранится в git. Чтобы начать с чистого состояния, остановите сервер, удалите `boris.db` и запустите снова.

## Главный сценарий на синтетических данных

1. Откройте страницу и проверьте дату и пять свободных слотов.
2. Выберите слот `11:00`, введите «Анна Тестова» и подтвердите запись. Слот становится занятым, в нём видно «Анна Тестова».
3. Во втором браузере откройте ту же страницу. Слот `11:00` занят «Анна Тестова».
4. Если во втором браузере страница была открыта до записи, попробуйте занять `11:00` как «Илья Примеров». Сервер вернёт отказ «Слот занят», в слоте останется «Анна Тестова».
5. Обновите страницу. Состояние не изменилось.
6. Отметьте кормление с ФИО «Илья Примеров». Карточка «Последнее кормление» обновится: в ней будет «Илья Примеров» и время отметки.

Отказ «Слот занят» в интерфейсе можно увидеть только со страницы, открытой до записи: на свежей странице у занятого слота нет кнопки записи. Поэтому для проверки DoD 4 второй браузер открывают заранее, до шага 2.

Используйте только синтетические ФИО. Реальные имена и рабочие данные в проект не вносятся.

## Бизнес-правила

Правила согласованы со студентом 2026-10-17. Пункты, которых нет в spec.md или которые его уточняют, отмечены *(уточнение)*.

| Тема | Правило |
|---|---|
| Борис | Пёс, как в spec.md. Описание GitHub-репозитория («кот») и название папки `cat-walking` с этим расходятся и подлежат исправлению. *(уточнение)* |
| Текущая дата | Считается на сервере по часовому поясу `Europe/Moscow`. После 00:00 по Москве появляются пять новых свободных слотов. Записи прошлых дней остаются в базе, но не показываются. *(уточнение)* |
| Прошедшие слоты | Свободный слот можно занять, даже если его время сегодня уже прошло. Это позволяет отметить состоявшуюся прогулку и проверять приложение в любое время суток. *(уточнение)* |
| Несколько слотов на одно ФИО | Разрешено. Без авторизации ФИО не проверить, поэтому ограничение было бы только видимостью защиты. *(уточнение)* |
| ФИО | Обязательно и не пустое после удаления лишних пробелов. Действует и для прогулки, и для кормления. |
| Конфликт записи | Сервер меняет слот одной атомарной операцией только в том случае, если слот свободен. Если слот уже занят, сервер возвращает конфликт с сообщением «Слот занят», без имени занявшего. После отказа страница показывает актуальное состояние слотов. *(уточнение текста)* |
| Обновление страницы | Чужие записи появляются при открытии или обновлении страницы и после собственных действий пользователя. Автообновления нет. *(уточнение)* |
| Время кормления | Ставит сервер в момент отметки, сотрудник вводит только ФИО. Ручного ввода времени нет. |
| Карточка кормления | Показывает последнюю отметку: ФИО и время. Если кормлений ещё нет, карточка сообщает об этом. *(уточнение пустого состояния)* |

## Технические ограничения

- Самостоятельное Node.js-приложение с запуском через npm.
- SQLite — единственное хранилище состояния, схема из spec.md: таблицы `walk_slots` и `feedings`. Никаких `localStorage`, состояния в памяти процесса, моков и статичной разметки вместо данных.
- Без новых фреймворков, внешних сервисов, API-ключей и инфраструктуры.
- Без секретов в репозитории. Все данные синтетические.
- Деплой не обязателен и в базовый результат не входит.

## Границы проекта

Не входят в проект:

- регистрация, авторизация, SSO, роли, личные кабинеты, справочник сотрудников;
- отмена, редактирование и администрирование записей и кормлений;
- уведомления, календарь на неделю, история действий, автообновление страницы;
- несколько собак, второй сценарий или второй MVP;
- реальные ФИО, рабочие данные, внешние интеграции;
- масштабирование, production-grade надёжность, обязательный деплой.

Это учебный проект, а не внутренняя система «Догяндекса». Полировка ведётся только до выполнения семи DoD из spec.md.
